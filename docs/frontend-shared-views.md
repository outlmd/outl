# `@outl/shared`: what the clients render

Every component and view piece in the shared library, with the Rust source each one mirrors.

Moved out of [`crates/outl-frontend-shared/CLAUDE.md`](../crates/outl-frontend-shared/CLAUDE.md), which is loaded into the model's context on every session in that crate.
The catalog is reference: you look an entry up before writing a helper, you do not read it top to bottom.
The decision rule for what may enter the library stayed in that file.

The surface is three pages, so grep all of them at once: `grep -n 'symbol' docs/frontend-shared-*.md`.

| `PageEmbedMap` (`Record<name, PageEmbedContent>`) + `<PageEmbedTitle name content? onOpenPage? />` — the `![[page]]` twin. Keyed by the **name as written in the token**, never by slug: the renderer holds `token.value` and nothing else. An absent key covers both "no such page" and "the resolve has not answered yet", and both render the literal `![[name]]` — a page embed is never blank, because the user wrote that name. The resolved line carries the same dim `↳ ` the TUI's chip and the expanded rows below it do, so all three clients say "this content lives elsewhere" the same way. Following it goes through the same `onRefClick` a `[[ref]]` uses (a page embed *is* a page reference, so a second handler would be a second answer to one question). **Both states are a plain inline `<span>`**: they swap after the first paint inside the block the user may be typing in, so an atomic inline box (`inline-flex`, an icon, `block`) would change the carrying line's height when a resolve lands and push every row below the caret — the component's own doc owns that reasoning, and `PageEmbed.test.tsx` pins the shape | `@outl/shared/markdown` | reply shape of `resolvePageEmbeds`; token `outl_md::InlineToken::PageEmbed` |
| `<CrumbTrail crumbs=… />` + `crumbTrailText(crumbs)` — a backlink's ancestor breadcrumb. The barrel carries only those two; `CRUMB_SEPARATOR` and the `TrailCrumb` prop type stay module-level, imported from `./CrumbTrail` by the test alone (the `lock.ts` rule). **Rendered, not drawn as source**: a crumb carries its own `tokens`, so a trail reads `#alinhamento buser/team/vendas internet 0800 email` instead of the markup around those names — the one line on the panel saying *where* a reference lives was the one line written in markup, with a URL eating a row that truncates to a single line. *Dimmed* is the caller's styling rule and composes with the token colours underneath; the component is **inert** (no `onRefClick` / `onTagClick` / `onLinkClick`), because the backlink row already has one destination and two tap targets in one line overlap on a phone. `variant="inline"` also keeps `blockAssets` false, so an image in an ancestor is a chip. `crumbTrailText` is the plain reading a `title=` tooltip can hold. | `<BlockProperties />` — a block's or page's `key:: value` properties as **one attribute line** under the text, and `attributeFields(properties, limit)` as the pure policy under it. A pill is a *tag* — a flat label you tap to filter — so drawing a field as one promised an action the tap did not perform, and two different things read as the same thing. This is the shape every mobile app gives an item's fields (Things, Linear, Apple Reminders, GitHub mobile): key in `fg_dimmer`, value in `fg_dim`, `·` between, one line, truncated. **Colour is spent only on a field that acts on the user** — `LIVE_KEYS` is `{remind}` today, and the criterion is *interruption*, not importance, which is why `auto-run` executes code and still renders quiet. A live field sorts first (the backend sorts alphabetically, so `remind` fell outside the capped line), shows its value without the key (the icon says what it is), and takes an SVG from `@outl/shared/icons` rather than the `⏰` the TUI draws, because `DESIGN.md` keeps emoji out of GUI chrome. Past `limit` fields the rest is `+N more`. **There is no inline editor**: the whole line is one tap target that calls `onOpen`, and editing lives in the client's properties sheet, where a row that looks like a form row opens a form. `propertyChips` is still the filter underneath — `isInternalKey` hides outl's own model state (`id`, `from-template`, `collapsed`) everywhere, and `isImportStamp(key, value)` hides an importer's leftovers from a *render* only, so a property editor still lists one and can delete it. **The type scale rides `rowClass`, never a class on the inner `<button>`**: mobile's `styles.css` carries an unlayered `button, input, textarea { font-size: inherit }`, which outranks every `@layer utilities` rule. One deliberate token divergence, recorded in [`docs/theming.md`](theming.md): the value uses `fg_dim`, not the dedicated `property_value_fg`, which the brand sets to `accent_soft` so the TUI paints every value lavender | `@outl/shared/markdown` | `isImportStamp` mirrors `outl_actions::property::is_import_stamp`; the glyph table still mirrors `outl-tui`'s `property_glyph` — a const can't cross the Rust/TS boundary, so each pair is edited together |

The style cache is what the inline `<head>` script replays before the first pixel | `@outl/shared/boot` | `outl_tauri_shared::commands::boot` (`BOOT_MARKS` is a declared mirror, pinned by that crate's `tests/boot_marks.rs` — a `&[&str]` has no serialized shape, so `wire_mirrors.rs` cannot hold it) |
| `onPagePreview(handler)` / `<PreviewOutline outline= />` — the page-first boot's client half. The backend reads today's journal `.md` and its sidecar **before** it opens the op log (0.6-1.3 ms on a real 730k-op workspace, against 163 ms of snapshot boot plus the index load) and emits it; this is what a client paints instead of a spinner or a skeleton. **`<PreviewOutline />` is a second outline renderer with no interaction in it at all**, and that is the design: the clients' real outlines are not separable from editing, and threading a "nothing works yet" flag through every mutation callback is wrong in exactly one direction. A renderer with nothing to make editable cannot drift into being editable, which is why the payload is a plain `PageView` and carries no "do not edit me" flag: a flag is a second, weaker statement of the same thing, and one a client can ignore | `@outl/shared/boot` | `outl_tauri_shared::page_preview`'s `page-preview` event |
| `paletteDeclarations(palette)` → the `<html>` inline declarations a palette installs, as a CSS string.
